# Slack for Omnichannel

Connect an existing Slack bot, receive human direct messages in the shared inbox,
and send private text replies through the existing recipient-consent and Approval
Center pipeline. Setup selects a verified sender; it does not enable dispatch or
schedulers. Public/group channels, edits, threaded replies, files, OAuth onboarding,
GovSlack and bulk sending are outside this release.

## Setup

1. Create/install an app at https://api.slack.com/apps. Bot scopes: `im:history`,
   `im:read`, `chat:write`. Enable messages on the app's Home tab.
2. In Credentials, enter the bot token, signing secret and app ID; Connect Slack.
3. Save the public HTTPS webhook URL in Connect & verify. In Slack Event
   Subscriptions, paste this URL and subscribe to `message.im`. Enable receiving.
4. Set the internal branding.
5. Enter a tester's Slack member ID. They must DM the app first. Confirm Send test
   message, confirm receipt, then Finish setup.

The signing secret comes from Slack; it is not generated by Odoo. Secrets remain
in encrypted private files below Odoo's data directory. Include this directory in
secure backups. Database/company/team/workspace/bot scopes are checked on reads.
Use a host-bound database (`dbfilter`) and a public HTTPS reverse proxy. Signature
verification uses original bytes, constant-time comparison and a five-minute
window. Signed retries deduplicate in the native inbox. The native worker handles
normalization and retention after acknowledging durable storage.

A setup diagnostic is fixed text and has a committed claim before external I/O.
Pending/accepted/uncertain sends cannot repeat; no automatic POST retry occurs.
Only a known definitive Slack rejection permits another explicit test. Receipt
withdrawal clears completion and deactivates the selected sender.

## Verification

`python -m unittest discover -s addons/omni_slack/tests`

`python addons/omni_slack/tools/check_install.py` creates/drops a disposable local
Odoo database, blocks external traffic/email, installs/upgrades, and checks native
forms, security, callback, inbox, reply binding and committed diagnostic behavior.

`OMNI_NODE_MODULES=<bundled node_modules> node addons/omni_slack/tools/test_ui.cjs`
renders the actual Owl 3 field and compiles setup inheritance on desktop/mobile.
Live Slack authentication/delivery still requires a real workspace and app.

## Approved replies

Select a Message approval type in channel settings, then explicitly click **Enable
approved replies**. Each recipient still needs confirmed consent and each message
still passes Approval Center. **Pause replies** stops new claims. A system
administrator separately enables the existing `omni_channel.cron_dispatch`
scheduled action; setup and reply activation do not change this global scheduler.
