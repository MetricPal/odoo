- Mock (boards 19.x): funnel by stage with drop-off, time in stage, lead source table (channel, campaign) with leads,

## 2. Channel performance (channel specialists, Senior, Head of department)

Question: how is each channel doing over time and what does it cost (the DE-CIX pattern, with our own data).
- Mock: one channel at a time (tabs or a Channel filter): KPI strip (sent, delivered, opened/read, clicked, replies,
  failed, cost, cost per click/lead), month-by-month trend with previous-period comparison, a scorecard table by month,
  a ranked list (best and worst mailings or posts), organic vs paid split where a channel has both.
- Data: `mi.plan.item` result fields per channel, the channel apps' traces (`mailing.trace`, `mm.trace`,
  `omni.social.publication`), spend lines by item. Social reach and platform analytics are not stored: show what exists
  and mark the rest "needs the platform connection".
- External data (LinkedIn page analytics, Campaign Manager, like the DE-CIX file): out of scope for this step; a
  separate decision (import file, or connect the account). Write it as a follow-up, not part of this report.
- Server: `mi.report.channel.get_overview(...)`; keep per-channel queries in one place to avoid N+1.

## Per report: the steps (about the same each time)

1. Announce the report and the question it answers; draw the mock as a Design artifact (3 boards: the Head view, the
   Senior or a state, and empty or missing data). Get approval.
2. Server model with `get_overview`; tests with a campaign, spend lines and CRM leads (as `test_executive.py`).
3. Client component, template and styles; register the client action; point the menu action at it.
4. Browser check on a test database with demo data (`--with-demo`, CRM installed) as the Head of department and a
   Senior; check scroll, the period switch, empty states, Print.
5. Docs (CHANGELOG, DESIGN.md), then commit when asked. Update the live database with `-u marketing_intel_reports`.

## Known pitfalls (from this work)

- The built-in browser pane must be visible: a hidden pane loads pages very slowly.
- After changing a static file open the page with `?debug=assets`; after changing a menu or action clear the browser's
  site data once (the web client caches menus).
- Restart the server after Python changes. The VS Code debug session can still hold port 8069 while a terminal server
  runs without a web port ("Address already in use"): stop one of them.
- Odoo 20 has no FontAwesome glyphs and `.o_hidden` hides elements; use words or `oi` icons with a title.
- Do not run `pkill -f` with a pattern that appears in the same command line.
